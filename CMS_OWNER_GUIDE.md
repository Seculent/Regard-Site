# РЕГАРД — инструкция по работе с сайтом

Админка сайта:

https://www.regard-spb.ru/admin/

Эта инструкция предназначена для обычной работы с объектами и новостями.
Редактировать файлы сайта вручную не требуется.

---

## 1. Вход в админку

1. Откройте:

   https://www.regard-spb.ru/admin/

2. Выполните вход через GitHub.

3. После входа доступны два основных раздела:

- Объекты
- Новости

---

# ОБЪЕКТЫ

## 2. Добавление нового объекта

Откройте:

**Объекты → Все объекты**

Нажмите:

**Добавить объект**

Заполните основные поля.

### Служебный ID

Используются только:

- маленькие латинские буквы;
- цифры;
- дефисы.

Пример:

`novoe-kolpino`

После публикации объекта ID лучше больше не менять.

### Название

Обычное название объекта, которое увидит посетитель сайта.

### Обложка

Главная фотография объекта для карусели.

Лучше использовать горизонтальную фотографию хорошего качества.

### Описание

Основной текст об объекте.

### Галерея объекта

Можно загрузить несколько фотографий.

Для объекта, который показывается в карусели, должна быть добавлена минимум одна фотография.

---

## 3. Черновик объекта

При создании нового объекта переключатель:

**Опубликован на сайте**

сначала лучше оставить выключенным.

Пока публикация выключена, объект можно спокойно заполнять и проверять.

Когда всё готово — включить публикацию.

---

## 4. Где показывать объект

У объекта есть два отдельных переключателя.

### Показывать в карусели объектов

Если включено, опубликованный объект будет показываться в разделе объектов на сайте.

### Показывать на карте

Если включено, опубликованный объект будет показываться на карте.

Для карты необходимо заполнить координаты.

---

## 5. Карта объекта

Для объекта на карте нужно указать:

- координаты;
- адрес.

Координаты вводятся в таком порядке:

1. широта;
2. долгота.

Например для Санкт-Петербурга:

`59.9386`
`30.3141`

Поле:

**Название в списке карты**

можно оставить пустым.

Тогда будет использовано обычное название объекта.

Цвет метки также можно не менять — будет использован стандартный цвет.

---

## 6. Скрытие объекта

Чтобы временно убрать объект с сайта:

выключите:

**Опубликован на сайте**

Удалять объект для этого не нужно.

Все его данные останутся в CMS.

---

# НОВОСТИ

## 7. Добавление новости

Откройте:

**Новости → Все новости**

Нажмите:

**Добавить новость**

Заполните:

- служебный номер;
- дату;
- заголовок;
- краткий текст;
- полный текст.

---

## 8. Служебный номер новости

Каждая новость должна иметь свой уникальный номер.

Для новой новости используйте номер, которого ещё нет.

У существующей новости номер лучше не менять.

---

## 9. Черновик новости

Новая новость может храниться скрытой.

Пока переключатель:

**Опубликована на сайте**

выключен, посетители сайта её не увидят.

Перед публикацией проверьте:

- дату;
- заголовок;
- краткий текст;
- полный текст.

После этого включите публикацию.

---

## 10. Скрытие новости

Если новость нужно убрать с сайта, необязательно её удалять.

Просто выключите:

**Опубликована на сайте**

Новость останется в CMS и её можно будет снова опубликовать позже.

---

# ИЗОБРАЖЕНИЯ

## 11. Загрузка фотографий

Фотографии можно загружать непосредственно через CMS.

Файлы автоматически сохраняются в специальную папку сайта.

Вручную копировать изображения в GitHub не требуется.

Перед загрузкой желательно:

- выбирать фотографии хорошего качества;
- не загружать несколько одинаковых файлов;
- давать файлам понятные имена.

---

# ВАЖНО

## 12. Перед публикацией

Для объекта:

- проверить название;
- проверить фотографии;
- проверить описание;
- проверить настройки карусели;
- проверить карту, если она используется.

Для новости:

- проверить дату;
- проверить заголовок;
- проверить краткий текст;
- проверить полный текст.

После этого включать переключатель публикации.

---

## 13. Если что-то пошло не так

Не пытайтесь вручную исправлять файлы сайта.

Не удаляйте объект или новость только потому, что их нужно временно скрыть.

Сначала выключите публикацию.

Если после сохранения что-то выглядит неправильно, обратитесь к человеку, который обслуживает сайт.

История изменений сохраняется в GitHub, поэтому опубликованные данные можно восстановить.
